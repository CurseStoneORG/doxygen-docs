24 // VillagePopulator — vanilla-style villages stamped into the terrain.
25 //
26 // Placement follows vanilla's village structure placement: a candidate
27 // anchor every 32 x 32 chunks, kept 8 chunks away from the region edge,
28 // salt 10387312 (the number vanilla uses for villages). The whole
29 // layout — where the well sits inside the anchor chunk, which way the
30 // village rotates, which piece every slot gets, and every road cell —
31 // is derived from a PRNG seeded only by (seed, regionX, regionZ), so
32 // every chunk that touches the village re-derives the IDENTICAL layout
33 // and writes only its own share of blocks. Nothing depends on
34 // generation order, and nothing can be half a village.
35 //
36 // The layout itself mirrors StructureVillagePieces.Start: the well at
37 // the center, four streets leaving it on the cardinal axes, houses and
38 // farms branching off each street on one side only (so pieces of
39 // different arms can never collide), and a street lamp near each well
40 // face. Every piece rotates so its door faces the road, exactly like
41 // vanilla turns its templates.
42 //
43 // The streets themselves are a small GRAPH, not stripes: everything
44 // starts at the well (the village's centre) and walks outward. Each arm
45 // gets a lane that leaves the well face, runs right along the door wall
46 // of every structure on that arm (so houses, farms and the street lamp
47 // all stay connected to the network) and weaves gently across its own
48 // corridor (a sine wave, so no street is a ruler-straight line); a
49 // couple of branches fork off the open side of an arm and wander away
50 // with their own curve, ending in a widened head — the little dead-end
51 // alleys that make a village look lived in. Every cell remembers the
52 // cell it walked from, which is what lets the terrain gate follow the
53 // ground step by step instead of judging every column against the well
54 // alone.
55 //
56 // Materials are chosen from the WELL's biome (vanilla picks the
57 // village's material set from its start piece): a desert village comes
58 // out sandstone and sand, a plains/savanna village oak and cobble.
59 // The well is also the start piece as a GATE: if it cannot stand
60 // (lake, river, cliff, another biome) the whole village is dropped,
61 // instead of leaving roads that lead to nothing.
62 //
63 // The terrain verdict — the well's biome, each piece's base height,
64 // the height and surface block of every column a piece or a road
65 // touches — is read ONCE per region and cached, because a chunk of
66 // terrain is expensive to evaluate and every chunk of the village used
67 // to ask the same questions again. Placing a chunk is then just block
68 // writing.

78 // One placed piece of a village layout, in WORLD coordinates: the
79 // top-left corner of the rotated footprint plus its extent.
80 struct VillagePiecePlacement {
81  int kind; // structure::village::PieceKind
82  int rot; // total quarter turns (piece rotation + village rotation)
83  int x, z;
84  int w, h;
85 };
86 
87 // The full layout of one region's village — a pure function of
88 // (seed, regionX, regionZ). populate() stamps exactly this, and the
89 // verification tools rebuild it through buildPlan() so they always test
90 // the real layout instead of a copy of it.
91 // One planned road column: its world position plus the index of the
92 // cell the road WALKED from (in pathCells; -1 = the cell leaves the
93 // well itself, so it is judged against the well's own ground). Parent
94 // indexes always point backwards, and after the layout drops the cells
95 // that fall inside a building every surviving cell still reaches a root
96 // through a chain of physically adjacent cells — the roads form one
97 // connected network hanging off the well.
98 struct VillagePathCell {
99  int x = 0, z = 0;
100  int parent = -1;
101 };
102 
103 struct VillagePlan {
104  std::vector<VillagePiecePlacement> pieces; // well first
105  std::vector<VillagePathCell> pathCells; // world road columns
106  int minX = 0, minZ = 0, maxX = 0, maxZ = 0; // world bounding box (half-open)
107  int wellCx = 0, wellCz = 0; // well centre (biome gate)
108 };

122  // Does this village actually generate here? False when the well's
123  // own footprint is unusable (lake, river, cliff, wrong biome) — the
124  // case where the whole village is dropped instead of leaving orphan
125  // roads. On true, outBiome/outWellH report the biome and ground
126  // level the village builds with (the biome decides its materials).
127  static bool villageStands(const TerrainNoise& noise, const VillagePlan& plan,
128  uint8_t& outBiome, int& outWellH);

130  // Nanoseconds this populator has spent on the calling thread. The
131  // verification tools read it to report the village's REAL marginal
132  // cost per chunk: timing whole chunks only measures the rest of the
133  // generator, which is an order of magnitude more expensive and
134  // differs from place to place (trees, caves, ore).
135  static uint64_t& nanosAccumulator();
