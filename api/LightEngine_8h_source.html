24 // LightEngine — sky and block light that actually behaves like vanilla.
25 //
26 // Before this, CurseStone had exactly one light pass
27 // (mcp_chunk_propagate_sky_light in the pure-C chunk layer) and it had
28 // three defects that match the reported symptoms one for one:
29 //
30 // 1. It only spread HORIZONTALLY. The BFS used the four neighbours
31 // (+x, -x, +z, -z) and had no vertical step at all, so light could
32 // never travel down through a cave mouth or under an overhang.
33 // Every covered area stayed pitch black — the "black patches
34 // under a ceiling" the player reported.
35 //
36 // 2. Block light was never computed at all. mcp_block_light_emission()
37 // existed and was dead code, so a torch or a glowstone emitted
38 // nothing into the chunk's block_light array and a cave lit only by
39 // torches was black.
40 //
41 // 3. Nothing ever updated the light after a block changed.
42 // World::setBlock() wrote the block and stopped, so building a roof
43 // left the room under it at full daylight, and breaking it left the
44 // room in the dark.
45 //
46 // This engine fixes all three: it floods in the six vanilla directions,
47 // seeds both layers, and recomputes a bounded region around every change
48 // (and around every newly loaded chunk, so chunk borders have no seam).
49 //
50 // Algorithm, per layer: clear the region, seed it (open sky from the
51 // heightmap / light emitters), seed it again from the light just OUTSIDE
52 // the region so nothing that flows in from the rest of the world is lost,
53 // then BFS outwards with a -1-per-step cost (more through opaque blocks).
54 // Clearing and re-flooding is what makes darkening work too: a roof going
55 // up simply lowers the seed value underneath it.

71  // change on every side can never miss a source further away: the
72  // recomputation is self-contained.
73  static constexpr int32_t kRelightRadius = 15;
