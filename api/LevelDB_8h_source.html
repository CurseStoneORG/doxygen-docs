24 // LevelDB — MCPE's default on-disk format (LevelDB-backed). C++.
25 //
26 // MCPE 0.15.x shipped with chunks stored in a per-world LevelDB.
27 // Keys follow the format `chunkX:chunkZ:_type` where `_type` is one
28 // of:
29 // 0x76 "v" full chunk data (legacy)
30 // 0x30 "0" block data + tile entities (newer)
31 // 0x31 "1" biome + state (newer)
32 // 0x32 "2" entity list (newer)
33 // 0x33 "3" block-extra-data (newer)
34 // 0x34 "4" heightmap + 2D block palette (newer)
35 //
36 // Full LevelDB support requires linking against Google's leveldb
37 // library. Phase 8 ships a stub that compiles cleanly with
38 // CURSESTONE_LEVELDB=0 and returns "chunk not on disk" for every
39 // request. When the build finds leveldb (via cmake/FindLevelDB.cmake
40 // and CURSESTONE_LEVELDB=1), a real backend lands in Phase 12+.
41 //
42 // Design rationale: keeping the API identical to anvil/Anvil means
43 // World::load() can pick a provider by name without format-specific
44 // special cases; the stub is the no-op implementation of that API.
