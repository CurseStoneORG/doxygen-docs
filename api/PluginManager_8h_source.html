23 // PluginManager — the two discovery paths of the plugin system:
24 //
25 // 1. FOLDER plugins (Lua): plugins/<Name>/plugin.yml with an entry
26 // script under src/ — loaded by the LuaPlugin backend.
27 // 2. FILE plugins (native): a bare plugins/<Name>.so or .dll dropped
28 // directly into plugins/ — no folder, no plugin.yml; the vtable
29 // descriptor inside the library is the manifest (NativePlugin).
30 //
31 // Both kinds load, enable and disable in one alphabetical pass and are
32 // disabled again on server shutdown.
33 //
34 // duplicates: two folders declaring the same plugin name, two folders
35 // with the same name, two native files with the same stem, or any
36 // folder/stem collision in the shared data_pl namespace all disable the
37 // copies involved with a warning. A native descriptor name that collides
38 // with an already-loaded plugin is rejected after load.
39 //
40 // It also ensures the data folders: <dataPath>/data_pl/ (server root, outside
41 // plugins/) and data_pl/<folder or stem>/ for every loaded plugin. the
42 // plugins only can touch its folder through the API data.*.
43 // Singleton: server::start flame loadAll() and server::runTickLoop flame
44 // disableAll() tras leaving of the tick loop.
