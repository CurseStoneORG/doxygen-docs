24 // NativeAPI — the C ABI contract between CurseStone and NATIVE plugins
25 // (.so on Linux/Android/macOS, .dll on Windows).
26 //
27 // A native plugin is a bare shared library dropped DIRECTLY into the
28 // server's plugins/ folder — no folder, no plugin.yml: the binary IS the
29 // plugin. It exports ONE symbol:
30 //
31 // const CsPluginVTable* CurseStonePlugin_entry(void);
32 //
33 // The vtable carries the plugin descriptor (name / version / author / api
34 // — the descriptor replaces plugin.yml as the identity source) plus its
35 // lifecycle hooks (onLoad / onEnable / onDisable / onUnload; only desc
36 // and onLoad are required). Everything the plugin can do goes through
37 // the CsPluginApi pointer handed to onLoad: plain C function-pointer
38 // groups, so plugins compile against ONLY this header and never link
39 // against the server binary. That keeps the ABI stable across builds and
40 // lets one .so work on any server built from the same SDK revision.
41 //
42 // The two load types the server distinguishes:
43 // 1. FOLDER plugins (Lua): plugins/<Name>/ with a plugin.yml manifest.
44 // 2. FILE plugins (native): plugins/<Name>.so or plugins/<Name>.dll —
45 // loaded exactly as dropped, manifest-free.
46 //
47 // RULES FOR PLUGIN AUTHORS:
48 // - Threading: every callback (events, tasks, commands) runs on the
49 // main thread, in the tick it was queued. Never block in a callback.
50 // - Lifetime: strings handed OUT by the API (event fields, argv,
51 // CsCommandSender::name) are owned by the server and are only valid
52 // until the callback returns. Buffers the plugin fills (char* out,
53 // uint32_t cap) are always caller-owned.
54 // - The CsPluginApi pointer received in onLoad must be passed back as
55 // the first argument of every context-bound call (log.*, scheduler.*,
56 // commands.*, events.*, data.*). Context-free groups (server.*,
57 // player.*, world.*) never take it.
58 // - A plugin callback must not call into the server after its own
59 // onDisable has run: the server removes listeners, tasks and
60 // commands before unloading the library.
61 //
62 // COMPATIBILITY: CS_PLUGIN_ABI_VERSION moves ONLY when an existing field
63 // changes meaning, type or order — a reorganisation, never a growth. New
64 // surface is added by APPENDING to the END of a group struct and the END
65 // of CsPluginApi: plugins compiled against an older header only ever
66 // touch the prefix they know, so they keep working unmodified, and a
67 // plugin built against this header detects an older server through the
68 // root apiSize field (compare against sizeof(CsPluginApi) as compiled)
69 // before calling any appended function. This keeps the plugin ABI at
70 // version 1 while the server's plugin API version (CURSESTONE_API) stays
71 // untouched between releases.
