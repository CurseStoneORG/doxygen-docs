18 // ChestDebug — per-chest trace from generation to the client.
19 //
20 // Follows one chest through the four stages where the 0.15 client can lose
21 // it, and records which stage broke so invisible-chest reports come with a
22 // diagnosis instead of a guess:
23 //
24 // 1. GENERATION LootChest writes block 54 + the tile blob, every seam the
25 // blob crosses (populate flush, spill, install drains,
26 // reconcile) with its block-match verdict.
27 // 2. REGISTRY World register/remove/heal of the TileChest.
28 // 3. WIRE FullChunkData 0x34 and BlockEntityData 0x32 for the
29 // chest, each with its BUILT / QUEUED / SENT stage and a
30 // monotonic sequence number so the report can prove the
31 // tile left AFTER its chunk. The tile NBT is re-parsed and
32 // validated against the era spawn-compound shape (id, x/y/z
33 // matching the packet header, no disk layout on the wire)
34 // plus a hex head for byte-level comparison against a
35 // network capture.
36 // 4. INTERACTION client taps, InventoryOpenEvent, ContainerOpen /
37 // ContainerSetContent, break + loot, save/load items.
38 //
39 // Every hook is a single relaxed atomic load when the mode is off; nothing
40 // allocates on the hot path. Enabled state is the /chestdebug command
41 // (operator-only). "SENT" always means "handed to the transport layer": the
42 // protocol carries no render confirmation, and reports say so instead of
43 // inventing one.
