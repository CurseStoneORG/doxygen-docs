CurseStone Plugin API

CurseStone plugins come in two load types, distinguished by what an operator puts into the plugins/ folder:

Load type What is dropped into plugins/ Manifest Runtime
Folder MyPlugin/ — a folder with a plugin.yml plugin.yml Bundled Lua 5.4 interpreter
File MyPlugin.so / MyPlugin.dll — a bare shared library none — the binary IS the plugin C ABI shared library (C++)

The rules in one line each:

  • Lua plugins are folder plugins: plugins/<Name>/plugin.yml with the entry script under src/.
  • C++ plugins are file plugins: drop the compiled .so (Linux, Android, macOS) or .dll (Windows) directly into plugins/. No folder, no plugin.yml, nothing else — the server opens the library, reads the descriptor inside it and that is the whole identity.

The plugin API version is CURSESTONE_API in src/CurseStone.h (currently 1.0.3).

Folder plugins (Lua)

# plugins/MyPlugin/plugin.yml
name: MyPlugin # identity; duplicates (case-insensitive) disable all copies
main: src/main.lua # entry script inside src/
api: 1.0.3 # required server plugin API
version: 1.0.0
author: YourName

Entry src/main.lua must return a table with optional onEnable / onDisable. The VM is sandboxed: no io, os, package or debug, and per-plugin instruction/time limits trip a circuit breaker.

API surface (globals):

  • log.info/warn/error(msg)
  • server.broadcast(msg), server.players(), server.getPlayer(name)
  • player.* — message, tip, popup, kick, teleport, teleportWorld, getWorld, isOp, getHealth, setHealth, setPermission, hasPermission, giveItem, setNameTag, getNameTag, setDisplayName, getDisplayName, getPosition, getRotation, setRotation, setMotion, kill
  • world(name) handles — getName, getSeed, getDimension, getTime, setTime, getBlock, setBlock, getSpawn, getPlayers, unload
  • commands.register(name, opts, fn), commands.reply(sender, msg)
  • events.on(name, fn) — PlayerJoin, PlayerQuit, PlayerChat, PlayerMove, PlayerDropItem, PlayerItemHeld, BlockBreak, BlockPlace, EntityDamage, EntityDamageByEntity, PlayerDeath, PlayerRespawn, PlayerBedEnter (alias PlayerSleepInBed), PlayerBedLeave, DoorToggle, PlayerInteract, InventoryOpen, InventoryClick, InventoryClose

  • plugin.include/import/getResource/saveResource/listResources

File plugins (C++ via .so / .dll)

Structure

The final plugin is ONE file, named after the plugin:

plugins/
SpawnProtection/ <- Lua plugin: folder + plugin.yml
plugin.yml
src/main.lua
HelloNative.so <- C++ plugin: the file itself
HelloNative.dll <- its Windows flavor (optional, may sit side by side)
  • No plugin.yml: name, version, author and the API the plugin was built for come from the CsPluginDesc the vtable returns.
  • No folder: the file sits directly in plugins/. The file stem (HelloNative from HelloNative.so) owns the private data folder data_pl/<stem>/ and doubles as the fallback display name.
  • Cross-platform flavors: HelloNative.so and HelloNative.dll may sit side by side; each platform picks its own extension. A lone foreign-extension file is skipped with a hint (MyPlugin.dll on Linux, MyPlugin.so on Windows) instead of a cryptic loader error.
  • Naming rules: the stem must be unique per server (case-insensitive), and the descriptor name must not collide with another loaded plugin — duplicates disable the copies involved with a warning.

The library exports ONE symbol:

const CsPluginVTable* CurseStonePlugin_entry(void);
CsPluginVTable

src/plugin/NativeAPI.h is the complete SDK header — copy it (or point -I at the server src/) and compile against it. The plugin links nothing: the entire server surface arrives as function-pointer groups in the CsPluginApi* handed to onLoad.

Minimal complete plugin

#include "plugin/NativeAPI.h"
extern "C" { // keeps the entry symbol's C name (no C++ mangling)
static CsPluginApi* g_api = nullptr;
static void onJoin(CsEvent* ev, void* ud) {
g_api->player->sendMessage(ev->player, "welcome!");
}
static void helloCmd(const CsCommandSender* s, int argc, const char* const* argv, void* ud) {
g_api->commands->reply(s, "hi from C++");
}
CS_PLUGIN_EXPORT const CsPluginDesc* myDesc(void) {
static const CsPluginDesc desc = {CS_PLUGIN_ABI_VERSION, "MyPlugin", "1.0.0",
"YourName", "1.0.3"};
return &desc;
}
CS_PLUGIN_EXPORT int myOnLoad(CsPluginApi* api) {
g_api = api;
api->events->on(api, "PlayerJoin", onJoin, nullptr);
api->commands->add(api, "hello", "Greet", "/hello", nullptr, helloCmd, nullptr);
api->scheduler->every(api, 100, heartbeat, nullptr);
return 0; // non-zero discards the plugin
}
CS_PLUGIN_EXPORT void myOnEnable(void) {}
CS_PLUGIN_EXPORT void myOnDisable(void) {}
CS_PLUGIN_EXPORT void myOnUnload(void) { g_api = nullptr; }
CS_PLUGIN_EXPORT const CsPluginVTable* CurseStonePlugin_entry(void) {
static const CsPluginVTable vt = {CS_PLUGIN_ABI_VERSION, myDesc, myOnLoad,
myOnEnable, myOnDisable, myOnUnload};
return &vt;
}
} // extern "C"

onLoad / desc are required; the other hooks may be NULL. The descriptor is the manifest: keep name non-empty and unique, and set api to the CURSESTONE_API you built against (an empty value means "this SDK"; an incompatible claim refuses the load).

Building

# Linux / macOS / Android NDK
gcc -shared -fPIC -O2 -I<repo>/src -o MyPlugin.so src/MyPlugin.cpp
# Windows (MSVC, x64)
cl /LD /O2 /I<repo>\src src\MyPlugin.cpp

Or with CMake (see plugins/HelloNative/ and the cursestone-example-plugin target):

add_library(MyPlugin SHARED src/MyPlugin.cpp)
target_include_directories(MyPlugin PRIVATE <repo>/src)
set_target_properties(MyPlugin PROPERTIES PREFIX "") # MyPlugin.so, not libMyPlugin.so

For Android use the NDK toolchain (-DANDROID_ABI=arm64-v8a and friends); for MSVC make sure the platform matches the server build (x64 vs x86).

Data folder

Every loaded plugin gets <server>/data_pl/<stem>/ created at load. The data.* group is jailed to it: relative paths only, no .., no backslashes. The Lua sandbox uses the same root, keyed by folder name.

Rules and guarantees

  • ABI version: CS_PLUGIN_ABI_VERSION (currently 1) is checked right after the entry lookup; a mismatch refuses the library with a clear log line. It only moves when an existing field changes meaning, type or order — new surface is appended to the end of the group structs.
  • Older/newer servers: a plugin built against a newer header than the server detects that through api->apiSize — compare it with sizeof(CsPluginApi) as compiled before calling any appended function.
  • Threading: every callback (events, tasks, commands) runs on the main thread. Never block inside a callback.
  • Safety: the library opens with RTLD_LOCAL (symbol-isolated from other plugins); every callback is wrapped so an exception is logged, not fatal; the command bridge re-resolves the plugin by name and registration id each execution, so /plugins reload can never call a pointer from a dlclose()d library.
  • Context-bound groups: log.*, scheduler.*, commands.*, events.* and data.* take the CsPluginApi* first; server.*, player.* and world.* are context-free.
  • Permissions mirror the Lua commands.register vocabulary: NULL/"" = public, "op" = operators + console, any other string = permission node.
  • String ownership: strings handed OUT by the API are valid only until the callback returns; buffers the plugin fills are caller-owned.

All functions return bool/int failure markers (false / -1 / 0) instead of raising anything; invalid arguments never crash the server.

Versioning

CS_PLUGIN_ABI_VERSION stays at 1 while fields are only appended; the server's plugin API version (CURSESTONE_API, currently 1.0.3) only moves at release time, not per change.

Commands

  • /plugins — lists every plugin; native ones show a [C++] tag.
  • /plugins reload — disables, unloads (dtor runs onUnload, library closed) and re-scans the folder (folders for Lua, bare files for C++), all on the main thread.

Reference implementation
