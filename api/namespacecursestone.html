Detailed Description

Writes a crash dump when the server hits a fatal error.

a world of the server (surface or Nether).

Defines Minecraft §-color/format codes and ANSI terminal colors.

Registry of server threads that are joined at shutdown.

Coordinates every memory-reclamation sweep in the server.

Produces a JSON file in the crash dumps directory plus a human-readable .log companion containing the backtrace, system info, server version, loaded plugins, and recent diagnostics context.

THE single global GarbageCollector for the whole server. There must be exactly ONE instance (Meyers singleton) and it is the only place that decides when memory is reclaimed.

Why one global GC: the codebase used to have several scattered reclaimers (Server::tick's chunk-unload sweep, World::tick's dropped-item sweep, Player::onUpdate's used_chunks_ cleanup, tile eviction) running on their own schedules. Independent schedules mean the world state players interact with (dropped items, open chests, loaded chunks) can disappear in the middle of a player action - the classic cause of pickup/inventory desyncs. Everything now funnels through collect(): the per-subsystem sweeps keep their cheap local bookkeeping, but any SWEEP THAT TOUCHES SHARED WORLD STATE only runs when the global GC authorizes it, on a single coordinated schedule.

Stores shared thread handles and joins every joinable one in joinAll(), clearing the registry afterwards.

Mirrors PMMP TextFormat + Terminal in a single C++ header.

Owns the world's settings (time, weather, and spawn). Multiple World instances can coexist on the same server; the server manages the map of active worlds.

The constructor instantiates the WorldProvider via WorldProviderManager according to the configured format and connects it to the ChunkManager so flushDirty() writes changes to disk; otherwise, the world would exist only in memory and changes would be lost on shutdown.
