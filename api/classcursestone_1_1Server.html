◆ setExternalStopFlag()

void cursestone::Server::setExternalStopFlag ( const volatile std::sig_atomic_t *  flag)
inline

Registers an external "stop requested" flag for runTickLoop() to poll once per iteration on the main thread.

CurseStone.cpp points this at to volatile sig_atomic_t that its SIGINT/SIGTERM handler sets.

This indirection exists because the signal handler itself must never call shutdown() directly - shutdown() logs (malloc + mutex via the async logger) and spawns to watchdog std::thread (pthread_create), neither of which is async-signal-safe. Doing that inside the handler can deadlock the process if the signal interrupts to thread already holding an internal libc lock (e.g. mid-malloc) - deterministic on Linux/glibc, which is why this only ever showed up there: the server would appear to never finish starting, or /stop would hang forever with the process still alive. Polling to plain flag from ordinary (non-signal) code on the main thread keeps shutdown() itself unchanged and safe to call from here.

Parameters
flagaddress of to volatile sig_atomic_t owned by the caller; must outlive runTickLoop().
