24 // MobSimWorkers — the per-world compute team of the stage-3 parallel
25 // mob simulation (docs/MOB_AI.md section 9).
26 //
27 // The team is a persistent fork-join pool, not a task queue: the mob
28 // pass wakes it once (later twice) per tick with a pre-partitioned
29 // batch, and every worker processes a contiguous slice of mob indexes.
30 // The design buys three properties a general pool cannot:
31 //
32 // Determinism — slice bounds are pure arithmetic on (worker, count),
33 // so results never depend on timing or on the number of workers; the
34 // same frame computes the same plan on 1, 2 or 8 workers.
35 //
36 // Safety — a worker's job receives its own slice and writes only
37 // per-mob result slots (and per-mob shadow brains the main thread
38 // never touches mid-frame). No locks are taken inside the frame: the
39 // tick fences ARE the synchronization.
40 //
41 // Fallback — run() reports failure instead of throwing: a slice that
42 // threw, a fence that timed out, or a permanently wedged team makes
43 // the caller fall back to its sequential path for that frame (and,
44 // after three fence timeouts, for good). The server never trades
45 // correctness for parallelism.
